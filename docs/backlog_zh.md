## B6/B7. 贡献分解改用隔离法 + 基带压缩纳入 nonlin 开关 —— ✅ 已落地(2026-08-03)

起因是给 B5 画"基带单独贡献"时发现两个问题,一个是缺陷,一个是**方法论错误**。

- **B6(缺陷)**:`BasebandStage.nonlin()` 只受 `baseband.enabled` 控制,
  `nonlin_enabled=False` 关得掉逐档 IM3、关不掉基带天花板。后果是分解图
  把天花板画进了标着"PN+ISI+IQ+ADC"的残余线里。`nonlin()` 增加 `enabled`
  形参,由 `RxChain` 传 `p.nonlin_enabled`;测试断言关掉后与"天花板够不着"
  的链路逐位一致(反向断言:开着时必须不一致,否则测试是空的)。
- **B7(方法论)**:原分解用**功率域相减**(全量读数减去残余底板)。这对
  随机源没问题,对**确定性源是错的**——相减出来的不是该源的功率,而是
  `|e_源|² + 2Re⟨e_源, e_其余⟩`,交叉项按 1/P₃ 走(斜率 −1),纯失真项按
  1/P₃²(斜率 −2),混合读数落在两者之间。
- **量化证据**:孤立立方原语(不接链路)扫 OIP3 给出精确的 **−2.00 dB/dB**,
  扫驱动给出 **+2.01**;链路内相减只有 **−1.49 / −1.37**。两项拟合
  `a/P₃² + b/P₃` 的 rms 残差 **0.14 dB**(单项模型 3.3–3.6 dB),拟合出的
  纯失真项斜率恰好 −2.00,且在 1.0 Vpp 处给 −46.80 dB —— 与孤立原语实测
  −46.90 dB 差 0.1 dB。交叉项占比:0.5 Vpp 时 19%,**1.0 Vpp 时 48%**,
  2.0 Vpp 时 76%。
- **排除的假设**:先怀疑是 ADC 削顶(摘掉天花板后峰值更高、参考被削更狠)。
  `ADCParams.enabled=False` 旁路后斜率纹丝不动(−1.49→−1.49),假设证伪。
- **改法**:`app/specs.py::run_rx_evm_sweep` 改为**隔离法**——每条曲线是
  只开该损伤的链路直接读数,不相减。能隔离的只有无校正的源(热噪声、
  非线性、相噪、ADC);IQ/DC/LPF 必须保持开启,因为它们的校正是减法型的,
  只关注入不关校正会注入等量反向误差。剩下的记为"隔离底板"并单独画出。
  开着基带段时,非线性进一步拆成 RF IM3(把摆幅推到 1e6)与基带天花板
  (把逐档 IIP3 推到 200 dBm)两条。
- **验证**:隔离法直接读出基带天花板 −46.3 dB,与交叉项修正后的推算
  −46.8 dB 一致(旧口径读 −43.8,偏悲观 2.5 dB)。
- **对设计结论的影响**:物理结论一条没变(天花板与天线功率无关、OIP3 是
  唯一杠杆),但**灵敏度被低估了**:真实斜率 −2 dB/dB,所以 1.0→1.4 Vpp
  实际买 5.8 dB 而不是 4.0 dB,ADC backoff 每加 1 dB 买 2 dB 而不是 1.37。
- **口径提醒**:隔离曲线**不满足功率相加**(确定性源之间相关,且每条都含
  隔离底板)。图注与 GUI 文本都写明了,不要拿它当预算表逐项加。

## B5. 基带段(LPF/VGA)噪声与非线性 —— ✅ 已落地(2026-08-02)

- **按基带的口径建模,不用 NF**:`impairments/baseband.py:BasebandStage` 以
  **输入参考噪声电压密度**(默认 6 nV/√Hz @基带节点)与**输出摆幅**
  (默认 1.0 Vpp ⇒ OP1dB +3.98 dBm @50 Ω)描述,另提供
  `from_rms_noise(v_rms, bw)` 接受积分噪声电压;dBm 只是内部表示。
  两个默认值是**按现有 8 档表反推的占位值,非电路数据**,替换各一行。
- **位置不对称是物理**:噪声注入在 **LPF 之前**(信道滤波器像硬件一样整形它),
  压缩施加在 **VGA 之后**(输出参考天花板)。
- **默认关**:开启需先用 `link.budget.deembed_states` 把官方表(级联总值)拆成
  RF-only 档位,否则噪声重复计算;拆解-再级联往返误差 0.0000 dB,
  基带占比 0.07 dB(state 0)→1.11 dB(state 7)。基带噪声若超过某档总值,
  函数直接报错点名该档(与档位表矛盾是结论,不是舍入)。
- **纠正了 B5 原始记录的一条前提**:"VGA 增益设置对 NF 的影响"**本来就已经建模**
  ——ADC 噪声在 VGA 之后,折算回输入时随 VGA 增益变化(state 7 从 VGA 40→0 dB
  时 NF 34.00→34.96)。基带噪声在 VGA **之前**,原理上不可能带来 VGA 相关的 NF;
  实测拆解前后 NF-vs-VGA 曲线逐点相同。真正随 VGA 变的是**线性度**。
- **新增的物理**(实测):
  1. 输入参考 IIP3 随 VGA 增益 **1 dB/dB 塌陷**(state 7:VGA 0/20/40 dB 下
     +11.1/−1.6/−21.4 dBm;lumped 模型恒为 +12.0 dBm);
  2. AGC 把 VGA **输出**钉在固定电平,所以输出天花板的 EVM 代价**与天线功率无关**
     ——实测 −40 dBm 与 −20 dBm 处均为 +2.55/+2.56 dB(−60 dBm 处仅 +0.08 dB,
     因为那里热噪声主导、RSS 上体现不出来)。
  3. 因此 **`adc_backoff_db` 从此有价**:160 MHz/1024-QAM、−40 dBm 输入下,
     lumped 模型最优 backoff ≈10 dB(−43.4 dB)且此后平坦;带 1.0 Vpp 天花板后
     最优推到 ≥18 dB(−42.8 dB),当前的 12 dB 要多付约 2.6 dB EVM。
     加大 backoff 与 ADC 量化噪声之间的折中曲线由 `link/baseband_study.py`
     的 `backoff_study` 现算。
- **验证**:`tests/test_baseband_stage.py`(10 项,含单位换算对拍手算值、
  拆解往返、"NF 不因此获得 VGA 相关性"的反向断言、默认关时逐位一致)。

### B9. Replay 对拍环节:照单施加交付残差,对上交付实测 EVM
- **状态**:可立即做(2026-08-08 记录,来源:对同类工程 wifi_rf_calibration 交付件的分析)。
- **动机**:现有检查器只判"每步是否达到其内嵌 spec",**抓不到遗漏**——一个根本
  没被交付的损伤项它永远看不见。同类工程靠这一环节发现了 14.4 dB 的在带失真
  无条目,那是逐项评审在结构上抓不到的缺陷类别。
- **做法**:从 cal-state JSON **外部**读出各步校后残差(TX/RX IRR、LO 泄漏、
  DC、IIP2、时延……),按 B10 的 `apply` 配方逐项注入干净 OFDM 波形,测出
  "解释得了的 EVM",与文件里 `final_loopback_evm` 的实测值对拍。
- **口径要求(必须遵守,同类工程的反面教训)**:闭合检验中**排除任何由实测
  解出的兜底项**。对方的 `tx_residual_evm_db` 由实测 EVM 反解,再进对拍,闭合
  是恒等式——实测:健康包 gap −0.00,把五个关键残差伪造成远好于实测
  (IRR 62→95、LOFT −72.7→−120 dBc 等)后 gap 仍 +0.14,零条 error。诚实口径
  (仅校准键)下同一个包 gap 是 −14.96 dB。结论以三个数交付:
  **解释 X dB / 实测 Y dB / 未解释 Z dB**,Z 单独成行,不并进总和。
- **层次约束**:replay 需要 numpy,放包内 CLI 与 GUI;独立检查器

- **注意**:被互斥规则或口径原因**丢弃不施加**的键必须逐个列名说明,不得静默
