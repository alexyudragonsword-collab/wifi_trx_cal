- **误提交构建暂存目录导致编译版 METADATA 冻结(2026-08-25,0.7.7)**:`build-android-wheel/`(197 文件 7.7 MB)混在 0.7.6 的 `git add -A` 里进了仓库。**危害不在体积**:`android_wheel.py` 用 `if not out.exists()` 缓存一个参考 wheel 来取 dist-info,于是这个陈旧副本让编译版的 METADATA(版本号、依赖表、requires-python)冻在 0.7.6——0.7.6 与 0.7.7 两轮出货的 wheel 都打着 `wifitrx-0.7.6` 的名字,而仓库里 `pyproject.toml` 已是 0.7.7。发现路径:核对 CI 里 wheel 文件名时读出版本对不上,不是任何守卫报出来的。已 `git rm --cached` + `.gitignore`;CI 增一步断言 wheel 文件名必须带 `pyproject.toml` 的版本号(匹配与不匹配两个方向都本地验过)。**顺带更正**:0.7.6 记的"57 个模块"含 5 个包 `__init__.py`,而那版起已不编译它们,实际 52。

## B14. EVM 估计器自拟合偏差(自由度修正)—— ✅ 已落地(2026-08-16,0.5.9)

- **发现途径**:11ac/n vs 11ax/be 同芯片对照实验。热噪声隔离读数两制式只差 +0.13 dB,而占用带宽比(18.91/16.25 MHz)要求 +0.66 dB——差值高度可复现(6 种子均值稳定),按"随测量配置漂移先怀疑仪器"排查。
- **机制**:`evm(equalize="per_tone")` 的逐音复增益由**被打分的同一批符号**最小二乘解出,期望吸收 1/N 噪声功率(N=符号数)。11n 帧 24 符号偏 −0.18 dB,11ax 帧 6 符号偏 **−0.79 dB**,0.61 dB 的制式相关仪器偏差恰好抵消 0.66 dB 的真实物理差。合成数据验证偏差律 10·log₁₀(1−1/N) 精确成立(N=4/6/12/24/96 全对上)。
- **修正**:`_evm_from_error` 加 Bessel 型自由度重标 N/(N−k)(per_tone k=每音 1 复参数 → n_sym/(n_sym−1);scalar 同理,量级可忽略);per_tone 现要求 ≥2 符号(1 符号时拟合吞掉全部误差,读数空洞,直接 raise)。
- **修正后实测**:20 MHz/64-QAM 热噪声差 +0.75 dB、MCS7 灵敏度差 +0.69 dB(11n −75.89 / 11ax −75.20 dBm),与理论 +0.66 吻合。**被推翻的结论**:此前"两制式灵敏度几乎相同(+0.09 dB)"是仪器伪影。
- **影响面**:所有绝对 EVM 读数上移 10·log₁₀(N/(N−1))(320M/4096 验收 −41.1→−40.2,未校 −25.7,规格 −38 余量 2.2 dB,docx 已同步);重放闭环 gap 两侧同一估计器、同步移动,判决带无需重标;270 测试零改动通过(余量足够)。与 P9(循环时延补偿)、洞察 6 同族:仪器的自证环节必须先于电路结论校准。

## B8. AGC 门限锚定带宽显式化(`agc_rebw` 开关)—— ✅ 已落地(2026-08-03)

- **背景**:出厂 8 档表的切换门限按平衡点公式
  `t_i = (2·IIP3_i + NF_{i+1} + (−174 + 10log10 BW)) / 3` **在 320 MHz 上解一次**,
  然后一套寄存器值用在所有带宽。平衡点随噪声底板走,也就是带宽变化的 1/3,
  所以 20 MHz 下出厂门限**偏高 4.0 dB**(10log10(320/20)/3 = 4.014),每一档
  都被留过了自己的平衡点——省下用不着的热噪声余量,去换现在要付的 IM3。
- **发现的不一致**:`_cal_setup` 里 `rx_hp` 分支按 320 MHz 重解,`baseband`
  分支却按**运行带宽**重解。同一个函数里两套锚定约定,谁也没写为什么。
- **改法**:锚定带宽提为显式变量 `anchor_bw`,三条路径统一;新增 GUI 开关
  `agc_rebw`(默认关 = 320 MHz 出厂约定,开 = 按本次带宽重解)。
  **这改变了 `baseband` 分支此前的行为**(原来恒按运行带宽,现在跟开关走);
  B5 的结论不受影响(天花板代价与输入功率无关),但此前 80 MHz 基带图上的
  切换门限位置偏低 2.0 dB。
- **实测收益**(20 MHz / 4096-QAM,强信号段 −52…−12 dBm,21 点):

  | | 出厂锚定 | 重解 |
  |---|---|---|
  | 平均 EVM | −41.8 | **−42.9**(−1.16 dB) |
  | 锯齿起伏 | −40.8…−43.6(2.8 dB) | −42.6…−44.0(**1.45 dB**) |
  | 最大单点收益 | | **−3.17 dB**(@−42 dBm) |

  结构非常干净:**两种配置落在同一档的 8 个点,差值恰好 0.00 dB**;收益全部
  来自换档位置不同的 13 个点(平均 −1.87 dB)。最差的那些点(−40.8)正是

## B6/B7. 贡献分解改用隔离法 + 基带压缩纳入 nonlin 开关 —— ✅ 已落地(2026-08-03)

起因是给 B5 画"基带单独贡献"时发现两个问题,一个是缺陷,一个是**方法论错误**。

- **B6(缺陷)**:`BasebandStage.nonlin()` 只受 `baseband.enabled` 控制,
  `nonlin_enabled=False` 关得掉逐档 IM3、关不掉基带天花板。后果是分解图
  把天花板画进了标着"PN+ISI+IQ+ADC"的残余线里。`nonlin()` 增加 `enabled`
  形参,由 `RxChain` 传 `p.nonlin_enabled`;测试断言关掉后与"天花板够不着"
  的链路逐位一致(反向断言:开着时必须不一致,否则测试是空的)。
- **B7(方法论)**:原分解用**功率域相减**(全量读数减去残余底板)。这对
  随机源没问题,对**确定性源是错的**——相减出来的不是该源的功率,而是
  `|e_源|² + 2Re⟨e_源, e_其余⟩`,交叉项按 1/P₃ 走(斜率 −1),纯失真项按
  1/P₃²(斜率 −2),混合读数落在两者之间。
- **量化证据**:孤立立方原语(不接链路)扫 OIP3 给出精确的 **−2.00 dB/dB**,
  扫驱动给出 **+2.01**;链路内相减只有 **−1.49 / −1.37**。两项拟合
  `a/P₃² + b/P₃` 的 rms 残差 **0.14 dB**(单项模型 3.3–3.6 dB),拟合出的
  纯失真项斜率恰好 −2.00,且在 1.0 Vpp 处给 −46.80 dB —— 与孤立原语实测
  −46.90 dB 差 0.1 dB。交叉项占比:0.5 Vpp 时 19%,**1.0 Vpp 时 48%**,
  2.0 Vpp 时 76%。
- **排除的假设**:先怀疑是 ADC 削顶(摘掉天花板后峰值更高、参考被削更狠)。
  `ADCParams.enabled=False` 旁路后斜率纹丝不动(−1.49→−1.49),假设证伪。
- **改法**:`app/specs.py::run_rx_evm_sweep` 改为**隔离法**——每条曲线是
  只开该损伤的链路直接读数,不相减。能隔离的只有无校正的源(热噪声、
  非线性、相噪、ADC);IQ/DC/LPF 必须保持开启,因为它们的校正是减法型的,
  只关注入不关校正会注入等量反向误差。剩下的记为"隔离底板"并单独画出。
  开着基带段时,非线性进一步拆成 RF IM3(把摆幅推到 1e6)与基带天花板
  (把逐档 IIP3 推到 200 dBm)两条。
- **验证**:隔离法直接读出基带天花板 −46.3 dB,与交叉项修正后的推算
  −46.8 dB 一致(旧口径读 −43.8,偏悲观 2.5 dB)。
- **对设计结论的影响**:物理结论一条没变(天花板与天线功率无关、OIP3 是
  唯一杠杆),但**灵敏度被低估了**:真实斜率 −2 dB/dB,所以 1.0→1.4 Vpp
  实际买 5.8 dB 而不是 4.0 dB,ADC backoff 每加 1 dB 买 2 dB 而不是 1.37。
- **口径提醒**:隔离曲线**不满足功率相加**(确定性源之间相关,且每条都含
  隔离底板)。图注与 GUI 文本都写明了,不要拿它当预算表逐项加。

## B5. 基带段(LPF/VGA)噪声与非线性 —— ✅ 已落地(2026-08-02)

- **按基带的口径建模,不用 NF**:`impairments/baseband.py:BasebandStage` 以
  **输入参考噪声电压密度**(默认 6 nV/√Hz @基带节点)与**输出摆幅**
  (默认 1.0 Vpp ⇒ OP1dB +3.98 dBm @50 Ω)描述,另提供
  `from_rms_noise(v_rms, bw)` 接受积分噪声电压;dBm 只是内部表示。
  两个默认值是**按现有 8 档表反推的占位值,非电路数据**,替换各一行。
- **位置不对称是物理**:噪声注入在 **LPF 之前**(信道滤波器像硬件一样整形它),
  压缩施加在 **VGA 之后**(输出参考天花板)。
- **默认关**:开启需先用 `link.budget.deembed_states` 把官方表(级联总值)拆成
  RF-only 档位,否则噪声重复计算;拆解-再级联往返误差 0.0000 dB,
  基带占比 0.07 dB(state 0)→1.11 dB(state 7)。基带噪声若超过某档总值,
  函数直接报错点名该档(与档位表矛盾是结论,不是舍入)。
- **纠正了 B5 原始记录的一条前提**:"VGA 增益设置对 NF 的影响"**本来就已经建模**
  ——ADC 噪声在 VGA 之后,折算回输入时随 VGA 增益变化(state 7 从 VGA 40→0 dB
  时 NF 34.00→34.96)。基带噪声在 VGA **之前**,原理上不可能带来 VGA 相关的 NF;
  实测拆解前后 NF-vs-VGA 曲线逐点相同。真正随 VGA 变的是**线性度**。
- **新增的物理**(实测):
  1. 输入参考 IIP3 随 VGA 增益 **1 dB/dB 塌陷**(state 7:VGA 0/20/40 dB 下
     +11.1/−1.6/−21.4 dBm;lumped 模型恒为 +12.0 dBm);
  2. AGC 把 VGA **输出**钉在固定电平,所以输出天花板的 EVM 代价**与天线功率无关**
     ——实测 −40 dBm 与 −20 dBm 处均为 +2.55/+2.56 dB(−60 dBm 处仅 +0.08 dB,
     因为那里热噪声主导、RSS 上体现不出来)。
  3. 因此 **`adc_backoff_db` 从此有价**:160 MHz/1024-QAM、−40 dBm 输入下,
     lumped 模型最优 backoff ≈10 dB(−43.4 dB)且此后平坦;带 1.0 Vpp 天花板后
     最优推到 ≥18 dB(−42.8 dB),当前的 12 dB 要多付约 2.6 dB EVM。
     加大 backoff 与 ADC 量化噪声之间的折中曲线由 `link/baseband_study.py`
     的 `backoff_study` 现算。
- **验证**:`tests/test_baseband_stage.py`(10 项,含单位换算对拍手算值、
  拆解往返、"NF 不因此获得 VGA 相关性"的反向断言、默认关时逐位一致)。

## B13. RX 闭合偏差归因与修正 —— ✅ 已落地(2026-08-09,0.5.1),**原假设被推翻**

- **原记录**(保留作对照):B12 扫描发现 RX gap +1.28 ± 0.41,当时归因为"缺调制下
  失真项(ADC 削顶 + 高斯尾)",计划用两电平分离交付 `rx_mod_dist_dbc`。
- **诊断推翻了它**(隔离法逐项对拍,3 个 seed):噪声/相位/ADC 各隔离项与交付
  数字全部吻合到 0.7 dB 内;**非线性隔离实测 −46.8,而 replay 注入的是 −44.9**。
  且 gap 符号是"多算"不是"漏算"——+1.28 的原始归因还叠加了一个 gap 符号读反。
- **真因(两层)**:① 注入配方把**实通带 IM3 系数(3/4 → c=8/3·√r)套在复包络
  立方上**;本模型 `y = x − x|x|²/P3` 的复包络双音系数是 1,正确常数 c = 2·√r,
  错配在功率上多算 **2.5 dB**;② 剩余 ~1 dB 是仪器细节。理论对拍:纯立方高斯
  不相关失真 2(S/P3)² = −46.1,乘带内分数 ≈ 隔离实测 −46.8 ✓。
- **修正与实测**:系数改 2·10^(dbc/20),`apply` 文本明确写出两种包络约定及混用
  代价;重扫 10 seed:RX gap **+1.28 → +0.42 ± 0.45**(absmax 1.18),10/10
  consistent;RX 带收回对称 **±2.0**,0.5.0 的"已知偏差"说明删除。验收判据
  |mean| ≤ 0.5 达成,无需新仪器。
- **教训入册**:配方常数也要有量纲/约定审计——同一个 dBc 数字,实通带和复包络
  的注入常数差 4/3;闭合检查连"检查器自己的换算错误"也能抓出来,前提是先把
  归因做对(隔离法对拍每一项,而不是给差值编故事)。
