D2 约定与护栏测试D2 Conventions and guard tests

D2.1 核心约定D2.1 Core conventions

真值注入模式:每个损伤带 enabled 开关与 injected() 真值;每个校准的验收 = 注入已知真值 → 估计 → 校正 → 与真值对拍。没有真值对拍的估计器不发数字。单位:模拟域 、数字域满量程,见教程第 2 章。fs 是数据集属性,由上层注入,分析函数不得自带缺省。CalResult 契约:estimated / corrections / trace / metrics_before/after / passed / saturated(触轨是与达标独立的余量事实)/ spec(内嵌验收规格,随文件走)/ cost(捕获预算)。确定性:全部随机源显式播种;比较性测试必须显式命名它测的配置,不许继承默认值。

The injected-truth pattern: every impairment has an enabled switch and injected() truth; every calibration's acceptance = inject known truth → estimate → correct → verify against truth. No estimator publishes a number without a truth cross-check. Units: analog , digital full-scale (tutorial ch. 2). fs is a dataset property injected from above — analysis functions must not default it. The CalResult contract: estimated / corrections / trace / metrics_before/after / passed / saturated (a railed trim is a margin fact independent of passing) / spec (the embedded acceptance limit that travels with the file) / cost (capture budget). Determinism: every RNG explicitly seeded; a comparative test must name the configuration it prices instead of inheriting defaults.

D3 如何扩展D3 How to extend

D3.1 新增一个损伤D3.1 Adding an impairment

五步,每步都有护栏盯着:① 在 impairments/ 建 dataclass,带 enabled 开关与 injected() 真值;② 接进 chain/params.py(TxParams/RxParams 字段 + randomize() 工艺分布 + injected() 汇总)并在 chain/tx.py 或 rx.py 的信号路径上消费它——死旋钮测试会强制每个字段真的被读取;③ 温度相关就加 tempco 字段并在 set_temperature() 里盖章;④ 在 tests/test_impairments.py 加旁路恒等(enabled=False 输出逐位不变)与真值效应测试;⑤ 若引入新包依赖,去 test_import_layering.ALLOWED 登记。

Five steps, each watched by a guard: ① create the dataclass in impairments/ with an enabled switch and injected() truth; ② wire it into chain/params.py (field + randomize() distribution + injected() rollup) and consume it on the signal path in chain/tx.py/rx.py — the dead-knob test enforces that every field is actually read; ③ if temperature-dependent, add the tempco field and stamp it in set_temperature(); ④ add a bypass-identity test (enabled=False leaves the signal bit-identical) and a truth-effect test in tests/test_impairments.py; ⑤ register any new package edge in test_import_layering.ALLOWED.

D3.2 新增一个校准D3.2 Adding a calibration

骨架:

The skeleton:

def calibrate_thing(tx, rx, ...) -> CalResult:
    before = measure()          # metrics_before
    est = estimate()            # from captures
    program(est)                # onto the chain
    after = measure()
    return CalResult(
        name='thing', estimated={...},
        corrections={...},      # what was programmed
        metrics_before=before, metrics_after=after,
        passed=after_meets_criterion,
        saturated=code in (0, code_max),
        spec={'metric': 'x_db', 'limit': -40.0,
              'sense': 'max'},
        cost={'captures': n, 'samples': n * length})

接线清单:① cal/deps.py STEP_REQUIRES 登记顺序约束(带物理理由——'为什么必须在谁之后'),planned_steps() 加入名字;温度敏感则进 TEMP_SENSITIVE;② cal/sequence.py run_full_cal 插入调用 + PROFILES 加捕获档参数;③ report/generator.py _PRINCIPLES 加中文原理段;④ 测试:≥3 种子 Monte-Carlo 收敛 + 真值对拍;⑤ 校正状态若含新的编程量,补进 correction_state()/load_correction_state()(交付 JSON 必须凭文件完整恢复芯片)。

The wiring checklist: ① register the ordering constraint in cal/deps.py STEP_REQUIRES (with the physical reason — why it must follow what), add the name to planned_steps(); temperature-sensitive steps also join TEMP_SENSITIVE; ② insert the call in cal/sequence.py run_full_cal and add its capture knobs to PROFILES; ③ add the Chinese principle paragraph to _PRINCIPLES in report/generator.py; ④ tests: ≥3-seed Monte-Carlo convergence plus an injected-truth cross-check; ⑤ if the step programs new state, extend correction_state()/load_correction_state() — the delivered JSON must restore the chip from the file alone.

D4 流程:CI、溯源与交付D4 Process: CI, provenance and release

D4.1 CI 双车道D4.1 The two CI lanes

push 车道跑 pytest -m "not slow"(护栏 + 单元 + offscreen GUI,约一分钟);每日车道跑全量(含慢速 e2e 与本文档的完整构建)。单解释器、无 OS 矩阵——护栏测试秒级就能抓住最重要的腐烂类别,矩阵只会稀释注意力。

The push lane runs pytest -m "not slow" (guards + unit + offscreen GUI, ~a minute); the daily lane runs everything including the slow e2e tests and this document's full build. One interpreter, no OS matrix — the guard tests catch the decay classes that matter in seconds; a matrix only dilutes attention.

D4.2 溯源纪律D4.2 The provenance discipline

每个生成的交付物(cal-state JSON、报告、handoff 输出、本 HTML)都盖 provenance() 章:git commit、dirty 标志(记录而非假设干净)、时间与关键库版本。检查器对 dirty 产物给警告。生成物中只有交付级文档入库(docx、本教程两份 HTML),运行产物(reports/、__pycache__)一律 gitignore。

Every generated deliverable (cal-state JSON, report, handoff outputs, this HTML) is stamped by provenance(): git commit, a dirty flag (recorded, never assumed clean), timestamp and key library versions. The inspector warns on dirty-tree artifacts. Only delivery-grade documents are committed (the docx spec and these two HTML files); run products (reports/, __pycache__) are gitignored.
